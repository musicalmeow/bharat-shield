Contact Management System Test - KMune

Secure contact management system implemented successfully!

System Overview

Security Features

  • Mutual Consent: Contact requests require acceptance
  • No Auto-adding: Users cannot be auto-added as contacts
  • User-Specific: Only messaging between accepted contacts
  • Minimal Data Exposure: Only essential user data exposed
  • Request Validation: Prevents duplicate and self-requests

API Endpoints

POST
/api/contacts/request

Send contact request between users

POST
/api/contacts/accept

Accept pending contact request

POST
/api/contacts/reject

Reject pending contact request

GET
/api/contacts/list/:userId

Get user's contact list

GET
/api/contacts/pending/:userId

Get pending contact requests

Database Schema

ContactRequest Model:

{
  fromUser: ObjectId,     // Who sent the request
  toUser: ObjectId,       // Who received the request
  status: String,         // "pending" | "accepted" | "rejected"
  createdAt: Date         // When request was sent
}

Updated User Model:

{
  username: String,
  publicKey: String,
  contacts: [ObjectId],  // Array of contact user IDs
  createdAt: Date,
  lastSeen: Date,
  isOnline: Boolean
}

Contact Request Flow

Step 1: Send Request

POST /api/contacts/request
{
  "fromUserId": "user123",
  "toUserId": "user456"
}

Response:
{
  "success": true,
  "message": "Contact request sent successfully",
  "requestId": "req789"
}

Validations:

  • Both users must exist
  • Cannot send to self
  • No duplicate requests
  • Users not already contacts

Accept/Reject Flow

Step 2: Accept Request

POST /api/contacts/accept
{
  "requestId": "req789"
}

Response:
{
  "success": true,
  "message": "Contact request accepted successfully"
}

Step 3: Reject Request

POST /api/contacts/reject
{
  "requestId": "req789"
}

Response:
{
  "success": true,
  "message": "Contact request rejected successfully"
}

Automatic Contact Addition:

  • When accepted: Both users added to each other's contacts
  • When rejected: Request marked as rejected
  • No automatic messaging until acceptance

Security Features

Data Protection

  • Minimal Exposure: Only username and publicKey shared
  • No Plaintext: No encryption logic in contact system
  • Request Validation: All inputs validated
  • Authorization: Users can only manage their own requests
  • Clean Separation: Contact system separate from messaging

Consent-Based System

  • Mutual Acceptance: Both users must agree
  • Explicit Actions: Clear accept/reject actions
  • No Auto-adding: No automatic contact creation
  • Status Tracking: Clear request status management
  • User Control: Users control their contact list

Test Scenarios

Scenario 1: Successful Contact Request

  1. Alice sends request to Bob
  2. Bob receives pending request
  3. Bob accepts request
  4. Both Alice and Bob added to contacts
  5. Both can now message each other
  6. Result: Secure contact established

Scenario 2: Rejected Contact Request

  1. Alice sends request to Charlie
  2. Charlie receives pending request
  3. Charlie rejects request
  4. Request marked as rejected
  5. No contact relationship established
  6. Result: Request properly rejected

Scenario 3: Duplicate Request Prevention

  1. Alice tries to send request to Bob again
  2. System detects existing request
  3. Returns appropriate error message
  4. No duplicate request created
  5. Result: Duplicate prevented
